- 从真实成功记录读取每个账号的成员和数字备注。无成功记录时跳过。已完成批次不重新生成，不覆盖当前保存历史。

- 缺名单使本批人数不足时，预览表会说明“结束本批剩余添加”，你确认后才将本批剩余添加结束；不补记人数或消耗编号。有未确认占用的活动批次不能自动结束。
- 确认时再次在同一事务里核查队列、成功成员、账号窗口和群绑定。任何一行变化或写入失败，全部账号的本次保存回滚；不会保存一半。重复保存同一冻结批次保留原 plan_id 和已选人证据。

各 Windows 电脑独立安装 Python 和 OCR 环境，分别使用不同名单和自己的数据库、编号及群窗口绑定。不复制另一台电脑的数据库或 `.ocr-env`。当前不跨电脑同步；以后需要共享进度再改进。

## 列表与失败处理

- 扫描显示全部 Telegram.exe 候选窗口，不把窗口数量宣称为真实已登录账号数量。必须由你核对。
- 旧账号备注按已有程序路径沿用。重启窗口导致编号改变时，不按扫描次序重新给旧账号起名。新窗口先分配唯一备注“账号01”等，可双击“账号备注”列修改；已有账号不在本页改名。
- 窗口最小化、弹窗或资料页未关闭、聊天搜索不为空、第一第二行不可见、条目不是支持的置顶群、报告不完整或同一程序打开多个窗口时，该行显示未确认及原因，其他窗口仍继续识别。
- 本版群列表适配已验证的英文和葡萄牙文标签；其他语言不猜测，显示失败后需报告适配。你现有两个测试窗口沿用原语言。
- 成功行默认全选。按 Ctrl 可调整本次确认范围；失败行不能确认。部分保存只包括你选中的成功行，其他旧配置保留。
- 确认前再次读取两次。任何所选账号的窗口身份、群名、控件标识或顺序改变，本次所选全部不保存，必须重新扫描核对。没有一次保存一半的情况。
- 未完成批次或未完成选人名单的绑定发生变化，拒绝覆盖原配置，先核查旧批次。同一绑定的重复识别允许刷新。已完成批次的历史名单和邀请核验不改写。
- 扫描只保存两个目标群的名称、顺序、语言、窗口及控件标识，不保存聊天消息预览。控件标识不是 Telegram 的稳定群 ID，正式打开目标群前仍按现有逻辑现场复核。

## 最终使用流程（分步接入中）

1. 打开全部账号，一次扫描并核对两个置顶群，确认保存。
2. 导入手机号和用户名，检查历史重复，分别保留进度。设置每个账号本次成功添加目标人数。
3. 所有账号依次添加，各自记录本批实际成功备注。编号全局连续，只在确认添加成功后递增，不按账号或计划人数预分配。
4. 添加流程结束后，你点击按钮启动全部账号群①搜索选人。每个账号只用自己的本批成功名单；停在最终 Add 前直接继续下一账号。所有选好后，你逐个点击 Add。
5. 你再点击按钮启动全部账号群②搜索选人，沿用同批联系人。脚本停在 Add 前，由你逐个确认邀请。
6. 不自动检测邀请成功，不因你点击某个账号群①的 Add 自动启动群②。实际入群结果由你确认后登记。

账号添加队列按本次独立批次设置人数。旧成功批次结束添加阶段并保留待邀请状态及原名单；新批次从0计算目标、继续全局编号。任何未确认联系人或暂停/待核查批次仍阻止自动建立新批次。没有添加过的空白批次可沿用。旧批次及邀请记录不删除、不确认成功。


### v0.6.47
支持英文 New Contact 未注册结果：唯一 AddContactBox、New Contact 标题、Try someone else 按钮且无输入框，两次只读一致才关闭。关闭核对后记录该号码失败，不计成功人数、不递增编号、继续下一手机号。未确认或未知失败仍停止。原提交超时且已人工重现同一号码时，可点击“核验原手机号未注册并继续”；不得用于另一个号码。


### v0.6.48
Create 后旧控件失效时，在原有200毫秒/10秒上限内仅重新读取结果，记录读取异常，不重复输入或 Create。已停止的原提交可在对应手机号资料页打开时点击“核验已提交资料页并继续”，两次核验匹配后登记成功并推进原队列；不重复创建。


### v0.6.49
Create 完成后立即发起两次资料页核验，不等待4秒定时轮询；成功登记后直接用同一对核验报告关闭上一位资料页（关闭前仍实时核对），避免再读两次相同资料页。跨账号、未注册跳过和人工恢复完成后立即推进下一步。未知状态保留原定时检查；不重复 Create，不减少成功核验。


### v0.6.50
添加前页面整理可关闭同一账号、同一窗口及群绑定的历史队列中已确认成功联系人的资料页，不再限于旧邀请名单。未确认记录不参与；原邀请名单和本次添加队列不改变。
